# 3D-пайплайн Vault: Blender в репозитории

Версия 1.0 · 2026-11-12 · фаза 0 · владелец зоны: Transport Maintainer, потребители —
Executor App (сцены), Spec Auditor (гейт бюджета).

## 1. Зачем это здесь, а не в песочнице

Песочница агента откатывается: всё, что установлено в `/tmp` или через `pip install`, исчезает
между ходами. Blender — 370 МБ, в Git его не положить. Поэтому в репозитории лежит **не
Blender**, а три вещи, которые делают его восстановление однокомандным и проверяемым:

| Файл | Что делает |
|---|---|
| `setup_bpy.sh` | создаёт venv, ставит `bpy==4.5.3`, собирает X/GL-стабы, делает обёртку `bpy-python` |
| `bpy_stubs.py` | пустые библиотеки-заглушки для `libGL`/`libXrender`/… — без них `import bpy` в headless-песочнице падает |
| `test_bpy.py` | смоук: куб → GLB → проверка accessor min/max, UV, материалов и Cycles-рендер в PNG |

```sh
tools/modeling/setup_bpy.sh --check      # ~370 МБ один раз, ~20 с на этом образе
```

Проверено на текущей песочнице (2026-11-12): `bpy 4.5.3 LTS`, `background=True`,
GLB/glTF-экспорт, UV и рендер Cycles CPU — зелёные.

**Правило для агентов.** Если для работы нужен инструмент, которого нет в образе, — сначала
скрипт установки в репозиторий, потом работа. Инструмент, установленный «руками в /tmp»,
считается потерянным при следующем откате и не может быть частью оракула.

## 2. Установка моделей: что даёт Blender, чего не даёт Three.js

Прошлый заход строил сцены процедурно (`LatheGeometry`, `TorusGeometry` в коде сцены) и
подключал готовые `.glb`. Результат: «модели очень плохие». Причина не в стиле, а в
способе: процедурная геометрия в рантайме — это всегда примитив, а не ассет.

Пайплайн Vault:

```
tools/modeling/scenes/<asset>.py     сцена Blender: геометрия, материалы, якоря, клипы
        │  bpy-python (headless)
        ▼
frontend/models-src/<asset>/         .blend + скрипты текстур + превью (исходники в Git)
        │  экспорт + оптимизация
        ▼
frontend/public/models/<asset>.glb   доставка: бюджет из budget.json
        │  audit_glb.py
        ▼
гейт: треугольники / вес / VRAM / материалы / primitive-группы
```

### 2.1 Что писать в Blender-сцене

- **Геометрия.** Один объект на функциональную деталь (корпус, дверь, ригель), не «один
  меш на всё»: анимация по объектам дешевле скиннинга.
- **Материалы.** Не больше 4 на модель. PBR: baseColor + metallicRoughness + normal.
  `transmission` (стекло) на мобильном — самый дорогой материал; допустим только на
  объекте, который занимает < 5 % экрана.
- **Якоря.** Пустышки с префиксом `Anchor_` (`Anchor_Flame`, `Anchor_Drums`, `Anchor_Light`) —
  по ним сцена цепляет VFX. Имена — snake_case, без `Cube.017`.
- **Клипы.** Короткие, авторены под окна UI: `idle` 2–3 с, `open`/`spin` 2–3 с, 24–30 fps.
  Скиннинг только там, где объектная анимация не выражает движение (ткань, персонаж).
- **Камер и света в файле нет.** Свет — в сцене Three.js, иначе настройки расходятся
  между экранами.
- **Масштаб.** 1 единица Blender = 1 метр, модель стоит на `y=0`, лицом в `+Z`.

### 2.2 Оптимизация перед экспортом

1. `meshopt`-сжатие и объединение primitive-групп: 23 группы у `safe.glb` — это 23 draw call
   на одну модель.
2. Нормали/касательные: касательные не экспортируются, если нет normal-map с
   `KHR_materials_normal`.
3. Текстуры ≤ 1024 px, PNG (WebView), атлас на модель, а не 7 файлов на монету.
4. Клипы: только те, что реально проигрываются; лишние каналы вырезаются.

## 3. Гейт бюджета

`tools/modeling/budget.json` — числа, `audit_glb.py` — проверка без Blender и без зависимостей.

```sh
python3 tools/modeling/audit_glb.py frontend/public/models/*.glb        # человеку
python3 tools/modeling/audit_glb.py --json <файл>                      # машине
```

Коды: `0` — в бюджете, `1` — превышения, `2` — файл не читается.

### 3.1 Текущее состояние (2026-11-12, до переработки)

| Модель | Треугольники | Вес | Текстуры | VRAM | primitive | Вердикт |
|---|---:|---:|---:|---:|---:|---|
| `safe.glb` | 20 054 | 1.82 МиБ | 5 (849 КиБ) | 18.7 МиБ | 23 | ✗ пять превышений |
| `rocket.glb` | 7 078 | 740 КиБ | 3 | 16.0 МиБ | 9 | ✓ |
| `coin.glb` | 1 536 | 404 КиБ | 7 | 8.3 МиБ | 3 | ✗ текстур 7 > 4 |

Суммарно 2.9 МиБ. Это и есть исходная точка фазы 0: две из трёх моделей формально не
проходят собственный бюджет, а «тормозило на ПК» означает, что на телефоне запас уже
отрицательный.

## 4. Что делать дальше (вход в фазу 1)

1. Пересобрать `safe.glb`: объединить primitive-группы, свести текстуры в атлас 1024²,
   вырезать неиспользуемые каналы клипов.
2. Пересобрать `coin.glb`: 7 текстур → 1 атлас (монета — самый частый объект на экране,
   её вес и draw call важнее, чем кажется).
3. Снять бюджет кадра на реальном устройстве (см. `docs/perf-budget.md`) и утвердить
   целевые FPS с Мастером.
4. После этого — новые ассеты только через гейт: `audit_glb.py` входит в проверку миссии.

## 5. Инструменты, которые можно добавить (решение фазы 0)

| Инструмент | Зачем | Когда |
|---|---|---|
| `gltfpack`/`gltf-transform` | meshopt/Draco, атласы, вырезание каналов | фаза 1, как только пойдут пересборки |
| MCP-сервер Blender | живая сцена под управлением агента | только если понадобится интерактив: headless `bpy` закрывает 90 % задач и работает в песочнице |
| `gltf-validator` (KHR) | формальная валидация GLB | фаза 1, вместе с гейтом |

Правило: новый тяжёлый инструмент входит в репозиторий скриптом установки с проверкой
версии/хеша, а не в чат «поставь себе».
