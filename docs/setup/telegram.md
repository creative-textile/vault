# Telegram: что делать сейчас и что подождёт

Версия 1.1 · 2026-11-12 · ответ на вопрос Мастера · статус: **принято** (D-113, D-115).
Дополняет `docs/environments.md` (контуры) и `.env.example` (переменные).

## 1. Короткий ответ

**Бот нужен уже сейчас, но он не «продукт» — он отдельный тестовый и живёт рядом.**
Демо-контур и без него работает: в браузере вход идёт через `demoLogin`, и весь продукт можно
проверять без Telegram. Бот нужен только для одного: чтобы пройти путь **«открыл Telegram →
нажал → открылся Mini App → вошёл по подписи»**. Это единственный путь, который нельзя
проверить в браузере, и именно он ломается чаще всего.

Поэтому:

- **сделано 2026-11-12:** бот **Vault Dev** `@my_vault_dev_bot` создан, Mini App `app` привязан
  (§1a). Боевых денег и публикации нет — это тестовый контур;
- **не сейчас:** продакшн-бот с брендовым именем, продакшн-домен и публичный Mini App — это
  фаза 2/3 (Go-Live), после того как ядро продукта и 3D приняты.

## 1a. Бот создан: что есть и что проверить

**Сделано Мастером 2026-11-12.** Бот **Vault Dev** — `@my_vault_dev_bot`, Mini App `app`:
`https://t.me/my_vault_dev_bot/app`. Публичная страница бота открывается, приложение привязано.

Что теперь проверить (это может только Мастер — вход в Telegram у него):

| Проверка | Как | Что должно быть |
|---|---|---|
| Mini App открывается | нажать в боте кнопку приложения | открывается страница Vault, а не белый экран |
| Приложение не пустое | посмотреть на экран | **сейчас увидим «Вход не выполнен: сервер API недоступен»** — это ожидаемо: backend на Vercel нет (D-111) |
| Реальная подпись | открыть `@my_vault_dev_bot` из Telegram, а не из браузера | входящий `initData` непустой; проверить можно только когда появится API |
| Имя для `.env` | скопировать из BotFather | `BOT_USERNAME=my_vault_dev_bot` (без `@`) |
| Токен | BotFather → API Token | положить в `.env` и секреты; **в чат не присылать** |

**Важно про `BOT_USERNAME` по умолчанию.** В `.env.example` стоит заглушка `vault_game_bot` — при
подстановке настоящего имени реферальные ссылки должны вести в **`my_vault_dev_bot`**, иначе
друг ведёт в чужой бот. Это проверяет сам backend при старте (пишет предупреждение в лог, если
`BOT_USERNAME` не совпадает с ботом из `BOT_TOKEN`).

**Чего ждать сейчас.** Приложение откроется и честно скажет, что API нет. Это не поломка бота:
привязан только фронтенд. Полная проверка «вошёл по подписи» — после того, как появится
бесплатный хостинг API (Ф2). Тогда же появится смысл в кнопках `/start`, `/play`, `/balance`.

## 2. Что конкретно сделать (5 шагов, делает Мастер)

1. Открыть `@BotFather` → `/newbot` → имя и юзернейм вида `vault_dev_bot` (не боевой).
2. `/newapp` → выбрать этого бота → задать название Mini App и **тестовый URL** (сейчас это
   Vercel-адрес `https://vault-frontend-rho.vercel.app`; после появления API — его адрес).
3. Положить токен в `.env` **локально** и в секреты CI/Vercel — **только Мастер**; в чат, Git и
   логи токен не попадает (R-SECRETS).
4. Записать юзернейм в `BOT_USERNAME` (без `@`) — от него зависят реферальные ссылки
   `https://t.me/<BOT_USERNAME>?start=<код>`.
5. Пройти путь руками один раз: Telegram → бот → Mini App → вход. Если вошёл по подписи, а не
   по демо — контур Telegram живой.

**Чего агенту делать нельзя:** регистрировать бота, вводить токен, менять настройки бота в
BotFather. Это доступы — зона Мастера (`R-MASTER-ONLY`).

## 3. Нормально ли, что Telegram и Vercel — не боевые

**Да, и это правильный порядок.** Боевой контур на этапе разработки не нужен и вреден: он
заставляет платить, публиковать недоделанное и пугает проверками. Нужна честная граница —
что именно не боевое и чем это грозит.

| Контур | Сейчас | Что это значит | Когда боевой |
|---|---|---|---|
| **Telegram-бот** | тестовый, `demo`-режим сервера | вход через `demoLogin` в браузере; подпись `initData` проверяется только при реальном боте | Ф2: отдельный бот, `DEMO_MODE=false`, боевой токен у Мастера |
| **Mini App URL** | Vercel preview/production | HTTPS есть, но **backend на Vercel нет** — `/api/*` отвечает 404, вход честно говорит об этом | Ф2: API на бесплатном хостинге, затем домен |
| **Домен** | `vault-frontend-rho.vercel.app` | свой домен не нужен, пока нет API | Ф3: домен, SSL, оферта |
| **База** | Supabase dev | данные тестовые, сброс допустим | Ф2: боевая база, бэкапы |

**Что не боевое НЕ отменяет:** подпись `initData` проверяется по-настоящему (`backend/src/services/user.ts`),
`BOT_TOKEN` в демо не нужен, но и не подделывается; в боевом режиме сервер **отказывается
стартовать** без `BOT_TOKEN`, `JWT_SECRET` и `ADMIN_TELEGRAM_IDS` — это защита от «включили
mainnet с демо-секретами» (`backend/src/index.ts`).

**Один риск, который надо назвать.** С `DEMO_MODE=true` любой, кто откроет приложение, входит
демо-аккаунтом. Для разработки это удобно; для «показать людям» — нельзя. Пока ссылка не боевая,
её и не показываем; переход в `DEMO_MODE=false` — отдельная карточка Ф2 с боевым ботом.

## 4. Что подготовить агенту (и когда)

| Работа | Фаза | Почему не раньше |
|---|---|---|
| Проверка подписи `initData`, `auth_date`, отказ устаревшим | **есть** | уже сделано в backend, покрыто смоуком |
| `BOT_USERNAME` в реферальных ссылках, проверка при старте | **есть** | бот сам пишет предупреждение при несовпадении |
| Тестовый бот + Mini App URL | **сейчас, Мастер** | без него не проверить путь входа |
| Карточка «боевой бот»: новый токен, `DEMO_MODE=false`, allowlist админов | Ф2 | нужны платежи и боевая база |
| Кнопка «Играть» и меню бота (команды `/start`, `/play`, `/balance`) | Ф2 | зависит от боевого бота и API |
| Уведомления в Telegram (результат дуэли, полёт ракеты) | Ф2–Ф3 | требуют стабильного API и антиспама |

## 5. Что я проверил в коде

- `backend/src/services/user.ts` — проверка `initData` по HMAC с `BOT_TOKEN`, `auth_date` с
  максимальным возрастом; при отсутствии токена вход честно падает, а не «пускает всех».
- `backend/src/index.ts` — в боевом режиме требует `BOT_TOKEN`, `ADMIN_TELEGRAM_IDS`, `JWT_SECRET`;
  `demo_token` считается отсутствующим.
- `backend/src/api/routes/user.ts` — `POST /api/auth/telegram` принимает `initData` и `refCode`.
- `.env.example` — `DEMO_MODE`, `BOT_TOKEN`, `BOT_USERNAME`, `WEBAPP_URL`, `ALLOWED_ORIGINS`,
  `ADMIN_TELEGRAM_IDS` описаны с предупреждениями.

Вывод: **код к Telegram готов, не хватает только бота и боевого API.** Это не блокирует миссию
V-1-1 (модели), но блокирует «проверить с телефона как игрок».
