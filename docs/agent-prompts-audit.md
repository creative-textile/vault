# Аудит промптов: что агент реально получает в задании

Дата: 2026-11-12 · основание D-111 · проверено по собранному бандлу `tools/script-cat/relay.user.js`
(45 исходных файлов, coverage 18 ruleId).

## 1. Короткий ответ

Промпты **в основном про Vault**, а не про прошлый проект: репозиторий, роли, зоны, маркеры,
очередь `Draft → Ready`, оракул `npm run verify`, поле `question` — всё это Vault и остаётся
верным. Но три места действительно остались от прошлой игры (2D-выживание с крафтом на Godot),
и одно из них давало агенту прямую ложь о стадии проекта. Их переписал, остальное не трогал.

| Что было | Откуда | Стало |
|---|---|---|
| `phases.bans`: «без платежей/**каталога**/загрузки/аккаунтов до их фаз; без **доли/валюты/комиссии**; ядро не open source без OSI» | прошлый продукт: каталог игр, доли авторов, OSI-лицензия ядра | запреты Vault без терминов чужой игры; номер фазы убран из текста |
| `i18n.rule`: «**8 локалей** (en, ru, zh-Hans, ja, pt-BR, de, fr, ko); текст только в каталогах» + путь `locales/**` | D-013…D-019 Godot-игры из `synapse`; в Vault каталогов перевода **нет** | «текст UI не хардкодь в разметку; строки отдельно от логики; диагностика код+параметры; языки решает Мастер» |
| Краткий регламент (приходит **в каждом** промпте): «сейчас активна **Ф0**, миссий нет, продуктовый код заморожен» | написан в фазе 0 и не обновлён | Ф1 «Ядро продукта и 3D», миссия V-1-1, код открыт только в границах scope |

Почему третье важнее двух первых: краткий регламент вшивается в бандл и приходит агенту вместе с
заданием. Агент 12 ноября получил бы «фаза 0, миссий нет» и либо отказался работать, либо счёл
карточку ошибкой — при том, что К1 уже лежит в Draft.

## 3. Визуал: SVG или генерация (новое, D-111)

Правило добавлено в `docs/art-direction.md` §7 и в краткий регламент §5a, поэтому приходит
агенту в каждом задании.

- **SVG** — иконки, лого, пиктограммы UI, рамки, болты, слоты, простые диаграммы. Вектор, чёткий
  на любом DPI, цвет из палитры, ≤20 КБ, без растровых вставок и внешних шрифтов.
- **Генерация изображения** — фоны сцен, ключевые кадры, атмосфера, обложки, референсы, текстуры.
  Агент обязан **открыть результат глазами** до сдачи: силуэт читается в 128 px, палитра наша,
  фон пригоден для вырезания.
- **Blender** — объём и силуэт; картинка 3D-модель не заменяет.
- Подмена инструмента — дефект: PNG вместо иконки, вектор вместо ключевого кадра.

## 4. Уставы ролей

Поле `Устав` в базе «Роли» — **URL**, и оно не подгружается в промпт автоматически (так написано
в `TEAM-PLAYBOOK.md`: имя, функция, зона и гейт приходят из базы, устав — нет). Поэтому устав
не «второй регламент», а ссылка на короткий документ роли для человека и для самого агента.

Заполнено:

| Роль | Устав | Статус в базе |
|---|---|---|
| Warden | `docs/agents/roles/warden.md` § Устав | Активна, Admin |
| Coordinator | `docs/agents/roles/coordinator.md` § Устав | Ждёт, Admin |
| Platform Architect | `docs/agents/roles/platform-architect.md` (новый файл) | Ждёт, нужен `Agent URL` |

Остальные роли — по мере ввода: файл устава + строка в «Ролях». Правило одно: устав не
расширяет зону записи; при расхождении верны `docs/REGULATION.md` и поле `Зона записи`.
