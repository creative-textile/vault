# Процесс Vault · локальная разработка через API

**Версия 2.0 · 2026-11-15.** Этот файл — неизменный system-prefix каждого
платного вызова. Он одинаков байт-в-байт для всех карточек фазы: провайдер
кэширует его, а `session_id = <фаза>/<карточка>` удерживает маршрут на одном
поставщике. Менять его можно только отдельным ADR и пересборкой доски.

Источник истины — Git. Notion, Google Drive, Arena-агенты и браузерный
транспорт не участвуют. Доска: `docs/board/index.html` (генерируется из
`tasks/`, `decisions/`, `verdicts/`, `costs/ledger.jsonl`).

## 1. Роли и зоны

| Роль | Что делает | Пишет |
|---|---|---|
| Мастер | направление, деньги, доступы, лицензии, финальные ADR, визуальная приёмка | всё; решения вручную |
| Coordinator | нарезка карточек, `draft → ready`, зависимости, причина возврата | `tasks/**` |
| Executor | код в своей зоне, локальные гейты, структурированный вердикт | `scope` карточки |
| Auditor | независимая проверка по артефактам, без правки проверяемого кода | `verdicts/**` |
| Acceptor | приёмка миссии по оракулу, а не по одной зелёной карточке | `verdicts/**`, статус миссии |

Зона (`zone` карточки) — граница записи. `git diff --name-only` сверяется с зоной
до выдачи. Чужая зона читается, но правится только карточкой владельцу.
`tools/local/**` — защищённая зона оркестратора: меняется отдельным ADR.

Оракул нельзя ослаблять никому, включая Acceptor и Мастера в рамках карточки:
проверки можно добавлять, но нельзя удалять, выключать и подгонять под код.

## 2. Карточка и статусы

Карточка — `tasks/<фаза>/<миссия>-K<n>.json`: `id`, `phase`, `mission`, `title`,
`status`, `role`, `model`, `mode`, `zone[]`, `contextFiles[]`, `decisions[]`,
`gates[]`, `oracle[]`, `invariants[]`, `acceptance`, `dependsOn[]`, `estimateUsd`.

`draft → ready → running → submitted → accepted | rework | blocked`.
Отдельно фиксируется `defect_owner: executor | statement`: брак работы и брак
постановки лечатся по-разному. `blocked` — пауза до Мастера, не тихий дефолт.

Зависимости: карточка выдаётся, только если все `dependsOn` имеют `accepted`.
Один ход — одна карточка; параллель только по разным зонам и по явному
разрешению в карточке.

## 3. Цикл хода (без браузера)

1. Coordinator переводит карточку в `ready`.
2. `tools/local/run.mjs` читает карточку, проверяет зону и зависимости.
3. **Бесплатные локальные гейты** (`gates[]`) идут до любого платного вызова.
   Красный rc = выдача запрещена, деньги не тратятся.
4. `budget check --add <оценка>`: при выходе за лимит фазы `$15` — `exit 2`.
5. `context-pack.mjs` собирает ≤12 000 токенов: system-prefix (этот файл) +
   файлы `scope` + нарезки ADR. Превышение — ошибка с разбивкой по секциям,
   не тихая обрезка.
6. Один вызов OpenRouter. Результат — **JSON по схеме** (никаких маркеров
   `CF_*` в последней строке): `status`, `summary`, `changed_files`,
   `commands`, `evidence`, `reason`.
7. `usage.cost`, токены и `cached_tokens` попадают в `costs/ledger.jsonl` с
   идемпотентным `call_id`. Повтор не удваивает списание.
8. Вердикт — `verdicts/<карточка>.json`; статус карточки обновляется в Git.
9. `npm run board` пересобирает доску; CI проверяет её свежесть.

## 4. Доказательство вместо отчёта

`not run`, тайм-аут, зелёный CI сам по себе и мок **не равны** pass.
Доказательство = команда + код возврата + наблюдаемый результат + SHA
артефакта. Каждое решение модели подтверждается **двумя независимыми
замерами**: двумя разными локальными инструментами (например `audit_glb.py` и
`validate_glb.mjs`, `tsc` и `npm test`), у каждого свой `result_sha`.
Повторный вызов той же модели за полную цену independence не даёт.
Визуальный критерий — человек открывает PNG и подписывает; числа его не
заменяют.

## 5. Деньги

Лимит фазы `$15`, план `$13.46`, warn на 80 % и 95 %. Факт берётся только из
`usage.cost` ответа OpenRouter; оценки из стека v3 — лишь для `check --add`.
Батч (−50 %) применяется к аудиту, приёмке и планам Coordinator: одна модель и
один endpoint на батч, результаты по `custom_id`. Батч не группируется по
`session_id`, поэтому тёплый кэш и −50 % не складываются — выбор делается по
факту из журнала. Исполнитель идёт синхронно с кэшируемым префиксом.
Маршрутизация: Argon — только деньги/ключи/миграции, ≤4 за фазу, по путям
диффа; Flash — карточки, где оракул полностью скриптовый; изображения —
сначала локальный Blender ($0), генерация только по остаточному принципу.

Секреты (`OPENROUTER_API_KEY`, `BOT_TOKEN`, `JWT_SECRET`, строки БД) не
попадают в Git, логи, промпты и вердикты. Ключ читается из локального `.env`.

## 6. Неясности, ADR, остановка

Неясность → `status: need_master` с причиной, карточка `blocked`. Дефолт и
истечение срока решением не являются. Изменение контракта, оракула, лимита или
границ продукта — ADR в `decisions/D-<номер>.md` с контекстом, тремя вариантами
и явным решением Мастера. Только Мастер решает: лицензии, деньги, платные
сервисы, доступы, боевые ключи, целевую аудиторию.

## 7. Инструменты

| Что | Команда |
|---|---|
| Все локальные проверки | `npm run verify` |
| Полный прогон с продуктом | `npm run preflight:full` (после `npm ci` в пакетах) |
| Бюджет / отчёт | `npm run budget:check` / `npm run budget:report` |
| Сухой прогон карточки | `npm run card:plan -- --card tasks/F1/<id>.json` |
| Выдача карточки | `npm run card:run -- --card tasks/F1/<id>.json` |
| Батч аудита | `npm run card:batch -- --role auditor` |
| Доска | `npm run board` |
| Blender | `npm run blender:check` |
| Python (Pillow/numpy) | `npm run py:check` |
| 3D-бюджет / GLB | `npm run modeling:audit`, `node tools/modeling/validate_glb.mjs` |
| Кадры сцен | `cd frontend && npm run eyes` (локальный Chromium) |
