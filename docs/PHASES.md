# Фазы разработки Vault

Версия **1.0** · 2026-11-12 · владелец: Мастер · хранитель: Warden.
Фазы — это рамки. Миссии — это работа внутри рамки. Одна фаза может содержать несколько миссий,
миссия не переходит в следующую фазу, пока её не приняли.

> **Где мы сейчас.** Фаза 0 «Подготовка» — активна. Продуктовый код заморожен: в `backend/`,
> `frontend/`, `bot/` не вносятся функциональные изменения до выхода из фазы 0. Разрешены только
> подготовительные артефакты (документы, инструменты, пайплайны, замеры, планы).

## 1. Правило номеров

| Что | Формат | Пример |
|---|---|---|
| Фаза | `Ф0`, `Ф1`, … | `Ф0 · Подготовка` |
| Миссия | `V-<фаза>-<номер>` | `V-0-2 · Пайплайн 3D` |
| Карточка | `<миссия>-K<номер>` | `V-0-2-K3` |

Номер миссии выдаёт Warden в ТЗ. Номер карточки — Coordinator в очереди миссии.
Свободный номер миссии не резервируется: пока нет ТЗ, миссии не существует.

## 2. Фазы

### Ф0 · Подготовка — активна

**Цель.** Понять, что именно строим и на чём, и подготовить инструменты так, чтобы тяжёлые
зависимости не терялись при откате песочницы агента.

**Что решается в фазе.**

| Вопрос | Выход фазы 0 | Кто решает |
|---|---|---|
| Производительность на телефоне (было: «сильно тормозило на ПК») | бюджет кадра, целевые FPS, профиль устройств, замер до/после | Platform Architect + замер |
| Качество 3D (было: «модели очень плохие») | художественный контракт, референсы, критерий «продукт, а не примитивы» | Мастер утверждает референсы |
| 3D-пайплайн в репозитории | `tools/modeling/**` + Blender как модуль `bpy` в песочнице, воспроизводимо | Transport Maintainer |
| Мультичейн-платежи | архитектура USDT: TON, BEP-20, ERC-20 (а не один TON) | Executor Chain + Security |
| Контур тестов без Docker | Supabase + Vercel как рабочий стенд | Platform Architect |
| Роли и регламент | состав команды, зоны, гейты, оракул | Warden |

**Что НЕ делается в фазе 0.** Новые игровые механики, новые экраны, боевые ключи,
включение `mainnet`, платная инфраструктура.

**Выход из фазы.** Все пять решений выше зафиксированы документами (`docs/PHASES.md` §3),
Мастер подтвердил состав фаз 1–5. Только после этого Warden выдаёт ТЗ первой миссии фазы 1.

### Ф1 · Ядро продукта и 3D

**Цель.** Привести игры к состоянию «работает на среднем Android без слайд-шоу и выглядит
как продукт».

**Внутри фазы (миссии, не ТЗ):**
- пайплайн моделей: генерация в Blender → оптимизация (gltf-transform/Draco/KTX2) → бюджет
  веса и VRAM → автопроверка ассетов;
- переработка сцен: бюджет кадра, LOD, инстансинг, отсутствие тяжёлых пост-эффектов на `low`;
- анимации: клипы вместо процедурных костылей, где это дешевле кадра;
- профилирование на реальном устройстве/эмуляции и отчёт «до/после».

**Приёмка фазы.** Замер на устройстве класса «средний Android»: стабильный целевой FPS,
вес сцены в бюджете, ни одного ассета вне контракта.

### Ф2 · Платежи и Go-Live инженерия

**Цель.** USDT в трёх сетях: депозиты, выводы, сверка, идемпотентность, режимы
`demo → testnet → mainnet`, бэкапы, SSL, мониторинг, нагрузка.

**Приёмка.** Прогон на testnet всех трёх сетей, подпись Security & Payments Auditor,
`go-live:check` зелёный.

### Ф3 · Публичный запуск

**Цель.** Боевой контур: домен, хостинг, лимиты, ToS, юридические ограничения азартных
механик. Ключи и включение `mainnet` — только Мастер.

### Ф4 · Рост

**Цель.** Удержание, новые механики, локали, аналитика. Стартует после стабильного прода.

## 4. Как фаза превращается в миссии

1. Warden пишет ТЗ миссии: цель, scope, оракул, инварианты, роли, DoD.
2. Coordinator режет ТЗ на карточки и выдаёт их по одной.
3. Роль работает в своей зоне, отвечает отчётом и маркером.
4. Spec Auditor проверяет по артефактам, Warden принимает миссию.
5. Миссия закрыта — фаза движется дальше. Незакрытая миссия не блокирует соседнюю зону,
   только если Warden явно разрешил параллель.

Правило одно и то же для всех фаз: **фаза без решений не открывается, миссия без ТЗ не
начинается, карточка без оракула не выдаётся.**
