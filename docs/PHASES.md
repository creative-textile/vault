## 2. Фазы

### Ф0 · Подготовка — **закрыта 2026-11-12**

Зафиксированы: бюджет кадра (30 FPS на слабом Android, `perf-budget.md`),
арт-контракт C+A (`art-direction.md`), мультичейн USDT TON → BEP-20 → ERC-20
(`architecture/payments-multichain.md`), контур тестов без Docker, состав ролей.
Vercel подключён к репозиторию, аудио-библиотека собрана, два языка ru+en,
тестовый бот `@my_vault_dev_bot`. Указатель действующих решений —
`../decisions/LEGACY.md`.

### Ф1 · Ядро продукта и 3D — **активна**

**Цель.** Игры работают на среднем Android без слайд-шоу и выглядят как продукт.

- пайплайн моделей: Blender 5.3 → glTF → бюджет веса/VRAM → автопроверка;
- два языка ru + en (`i18n.md`) — отдельной миссией после V-1-1;
- Telegram-контур (`setup/telegram.md`): тестовый бот сейчас, боевой в Ф2;
- сцены: бюджет кадра, LOD, инстансинг, анимации клипами;
- профилирование на реальном устройстве, отчёт «до/после».

**Приёмка.** Замер на «среднем Android»: целевой FPS, вес сцены в бюджете,
ни одного ассета вне контракта, визуальная подпись Мастера.

### Ф2 · Платежи и Go-Live инженерия

USDT в трёх сетях: депозиты, выводы, сверка, идемпотентность,
`demo → testnet → mainnet`, бэкапы, SSL, мониторинг, нагрузка.
**Хостинг (D-126):** без Docker — Vercel (фронт), Render (backend + бот),
Supabase (Postgres), GitHub Actions (CI), Free-тарифы; `render.yaml` включается
этой миссией, см. `DEPLOY-FREE.md`. Проверить cold start / паузу Supabase /
нужность Redis и решить вопрос 152-ФЗ до реальных игроков.
**Приёмка.** Прогон на testnet всех трёх сетей, подпись Security & Payments
Auditor, `npm run go-live:check` зелёный.

### Ф3 · Публичный запуск

Боевой контур: домен, лимиты, ToS, юридические ограничения азартных
механик; хостинг — выбранный в Ф2 free-стек или локализованный fallback по 152-ФЗ.
Ключи и `mainnet` — только Мастер.

### Ф4 · Рост

Удержание, новые механики, локали, аналитика. Стартует после стабильного прода.

## 4. Как фаза превращается в миссию

1. Мастер/Acceptor утверждает `mission.json`: цель, scope, оракул, инварианты, DoD.
2. Coordinator режет на карточки `tasks/<фаза>/*.json`, `draft → ready`.
3. `npm run card:plan` (офлайн) → `npm run card:run` (гейты → бюджет → вызов).
4. Auditor проверяет по артефактам, Acceptor принимает **миссию** по оракулу.
5. `npm run board` обновляет доску; факт расходов — в `costs/ledger.jsonl`.

Правило одно для всех фаз: **фаза без решений не открывается, миссия без ТЗ не
начинается, карточка без оракула не выдаётся, лимит фазы не превышается.**
