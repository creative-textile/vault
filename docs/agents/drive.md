# Drive: раскладка и артефакты

Корень проекта: `Arena/<project>`. Три служебные папки, файлы в корне Диска не
являются ни журналом, ни payload, ни валидным артефактом хода.

| Папка | Назначение | Имя | Создатель |
|---|---|---|---|
| logs | машинный журнал попытки, append-only | `<dispatch_id>_<run_id>.md` | ScriptCat через Gateway |
| payloads | входные большие задания; большое задание доставляется указателем | свободное безопасное имя; снимок прогона `<dispatch_id>_<run_id>__assignment.md` | Gateway; снимок прогона — ScriptCat через `savePayload` |
| artifacts | свободные результаты агентов | `<dispatch_id>_<run_id>__<slug>.<ext>` / D-031 (ниже) | агент через Gateway / Drive-коннектор с проверкой ScriptCat |

Ручной артефакт: `manual__<project>__<slug>.<ext>`.

**Адрес папки в промпте (D-035).** Исполнитель/аудитор/ревьюер получают блок
`drive.artifacts` с адресом `Arena/<project>/artifacts` и запретом корня Диска —
раньше раскладку видел только Координатор, и отчёты аудитора оседали в корне.
Имя проекта подставляется из профиля (`driveFolder`). Файл в корне Диска
артефактом не считается; уже созданные в корне отчёты переносятся в `artifacts`
без переименования (D-031) и без смены ID/URL.

## Payload-канал (D-034)
Большое задание (длиннее `payloadInlineMax`, по умолчанию 1500 символов) не
инлайнится в промпт. Транспорт на каждый прогон фиксирует снимок задания в
`payloads` через `savePayload` (`<dispatch_id>_<run_id>__assignment.md`) и шлёт
агенту короткий указатель на него. Оракул (`Acceptance`) и `Scope` остаются в
промпте — файл их не заменяет и не ослабляет. Малое задание остаётся инлайном.
Отказ шлюза — явная ошибка, не тихий инлайн. Агент читает файл задания до работы;
ссылка и ID приходят в промпте.

## Артефакты (Gateway 1.8.0, D-031/D-033)
- MIME-whitelist: `text/plain`, `text/markdown`, `application/json`, `text/csv`,
  `image/png`. Расширения: `md`, `txt`, `json`, `csv`, `png`.
- Имена: legacy `<dispatch_id>_<run_id>__<slug>.<ext>`, ручной
  `manual__<project>__<slug>.<ext>` и схема D-031
  `<МИССИЯ>__<КАРТОЧКА>__<вид>__<дата или SHA>.<ext>`
  (вид: `report|evidence|audit|logs|shot`; опционально `__supplement-N`).
  Пример: `VAULT-1__K-15__evidence__e19a8d3.txt`, `VAULT-P1__P-A__shot__2026-11-04.png`.
- PNG передаётся в `saveArtifact` как base64 (`encoding: "base64"`); размер
  считается по декодированным байтам. Текст — в UTF-8. Максимум 262144 байт
  (`Utilities.newBlob(content).getBytes().length` для текста): кириллица занимает
  2 байта на символ, и текст, проходящий по `string.length`, может превышать
  байтовый лимит — такой файл отклоняется.
- Подкаталоги: по умолчанию плоско. Явный `subdir` создаёт/использует
  `artifacts/<МИССИЯ>` только для схемы D-031, имя подкаталога равно миссии;
  один уровень, вложенные пути и подкаталоги для legacy/manual запрещены.
  Создание подкаталога — решение Warden/Мастера (D-031), не импровизация агента.
- `saveArtifact` кладёт файл в `artifacts` или его подкаталог первого уровня;
  файл в корне/чужой папке отклоняется (`verifyArtifactPlacement`). Идемпотентная
  миграция усыновляет существующую папку `artifacts`, не пересоздаёт её и не
  меняет ключ проекта.
- Дубликат имени: совпало имя и содержимое (побайтово) — `duplicate`; совпало
  имя, но содержимое другое — явный конфликт («возьмите новое имя»), а не
  молчаливый возврат старого отчёта.
- `read` остаётся текстовым: PNG не читается как UTF-8, для него используется
  `verifyArtifactPlacement`. Необязательное поле `artifacts` в `CF_AGENT_RESULT`
  — массив ссылок на эти файлы.

## Телеметрия остановки (D-073)
На остановке и на восстановлении транспорт выгружает состав журнала попыток и
структурный снимок страницы — файлом в `artifacts`, не чаще одной записи на
событие (не каждый тик). Имя — по схеме D-031, когда миссия и карточка известны,
иначе ручной артефакт `manual__<project>__heal-<вид>__<дата>.json`. Переписки и
секретов в файле нет: снимок считает элементы и длины, строки проходят очистку,
query-строки адресов вырезаются. Если есть GitHub-токен, та же телеметрия ложится
в `telemetry/` проекта коммитом. Предел — `healTelemetryMaxBytes` (200 000 Б),
то есть заведомо ниже лимита артефакта шлюза (262 144 Б).

## Реестр
`CF_GATEWAY_PROJECTS_V1` хранит `logsId`, `payloadsId`, `artifactsId` на проект.
Миграция 1.6 → 1.7 добавляет `artifactsId` без смены ключа и без потери истории;
1.7 → 1.7.1 меняет только проверку размера и дубликатов; 1.7.1 → 1.8.0 добавляет
имена D-031, PNG/base64 и подкаталог миссии по явному запросу. Ключ и папки
проекта не меняются; ретро-переименование старых артефактов запрещено (D-031).
