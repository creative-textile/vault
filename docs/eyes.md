# 👁 Как агент видит анимацию

**Дата:** 2026-11-12. **Решение:** D-120. **Инструмент:** `frontend/tests/eyes/frames.mjs`.

## Проблема

Агент не видит анимацию. Числа проверяют математику (`tests/scene-math.mjs`), но не
проверяют, что на экране **что-то нарисовалось**. Чёрный кадр, уехавшая камера,
лопнувший материал, пустая сцена — по числам «всё в порядке».

## Что проверено в песочнице агента (и почему не работает)

| Способ | Результат |
|---|---|
| Chromium из `@sparticuz/chromium` | распаковывается, но падает: нет `libnspr4/libnss3` |
| `apt-get install` | заблокирован: `deb.debian.org` недоступен (`Empty reply from server`) |
| `sudo` | есть, но скачивать нечего |
| Сборка `gl` (headless-gl) | не собирается: нет `libGL` и заголовков |
| `cdn.playwright.dev` | недоступен |
| Скачать артефакт CI | недоступен: `productionresultssa*.blob.core.windows.net` закрыт |

**Вывод:** браузер нужен там, где он есть — в CI. А чтобы агент мог получить
результат, канал должен идти через `api.github.com` (он открыт).

## Как работает

1. CI-шаг ставит реальный Chromium: `npx playwright install --with-deps chromium`.
2. `frames.mjs` поднимает **dev-сервер** Vite (не `preview`!) и снимает
   `/scenes.html` — готовую отладочную галерею сцен, которой не нужен ни backend,
   ни база, ни авторизация.
3. WebGL без GPU: `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`.
4. 12 PNG на отрезке 6 с + `report.json` (версия WebGL, ошибки страницы).
5. Кадры уезжают артефактом `scene-frames` **и** сводная картинка коммитится
   в ветку как `frontend/frames/preview.jpg` — её агент читает через `api.github.com`.

## Две ловушки, которые нашлись только на практике

**1. `vite preview` не годится.** `scenes.html` намеренно не входит в прод-сборку.
`preview` раздаёт `dist/`, на неизвестный путь отдаёт `index.html` — и первые кадры
показывали онбординг «Витрина хранилища» вместо 3D-сцен. При этом HTTP был **200**.
Поэтому сервер проверяется по содержимому (`scenes.tsx`), а не по коду ответа.

**2. Пути.** У job `working-directory: frontend`, поэтому `cd frontend/frames`
удваивал путь и ронял шаг. Отсчитывать от `frontend/`.

## Что видно на первых настоящих кадрах

- Сцены рисуются: туманность, звёзды, площадка с циановым кольцом и золотой разметкой, ракета.
- **Кадр 0 — пустой в CI.** В софтверном рендере (SwiftShader) первый кадр
  появляется через ~1.5–2 с. Мастер такого в реальном браузере не видел — значит
  на GPU это не проблема игрока, а артефакт CI. **Но** «не видел» ≠ «невозможно»:
  на слабом телефоне компиляция шейдеров тоже занимает время. Поэтому в сцене
  сознательно оставлен двухсекундный прогрев (`firstFrameAt + 2000` в
  `lib/stage.ts`): решения о качестве принимаются только после него.
- **FPS 6–9 в CI — не показатель.** SwiftShader считает на CPU. Гейт 30 FPS
  проверяется только на реальном устройстве; кадры из CI про FPS не говорят ничего.

## Как пользоваться

```bash
# локально (нужен браузер; в песочнице его нет — скрипт мягко выйдет с кодом 0)
npm run eyes -- --frames 12 --span 6000

# в CI: кадры уезжают артефактом + сводка в ветку
gh api "repos/creative-textile/vault/contents/frontend/frames/preview.jpg?ref=<ветка>" \
  -H "Accept: application/vnd.github.raw" > preview.jpg
```

## Границы

- Это **кадры**, а не видео: движение оценивается по последовательности, не по плавности.
- Звук так не проверить — только осциллограммой (`tools/audio/audit_audio.py`).
- «Как ощущается на телефоне» не проверить никак. Это остаётся за Мастером.
