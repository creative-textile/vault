# Регламент · краткая версия (вход для агентов)

Версия 1.6 · 2026-11-12. Вход, а не весь регламент: полная версия — страница «Регламент команды
Vault» в Notion (ссылка в промпте), репозиторная копия — `docs/REGULATION.md`. При расхождении
верна полная. Этот текст уже пришёл в твоём задании: страницу регламента открывать и листать
не нужно.

## 1. Роли (имена заморожены для Vault)

| Роль | Функция | Делает |
|---|---|---|
| **Мастер** | Owner | направление, доступы, лицензии, деньги, финальные ADR; секреты и боевые ключи вводит только он |
| **Warden** | Reviewer | ТЗ миссий, приёмка по оракулу (accept/rework/master), ответы на вопросы и ADR |
| **Coordinator** | Coordinator | очередь `Draft → Ready`, нарезка карточек, «Итог»; код и PR не пишет |
| **Executor App** | Executor | фронтенд, бот, API и сервисы продукта, кроме платежей |
| **Executor Chain** | Executor | TON, BEP-20 и ERC-20: приём депозитов, выводы, сверка ончейн |
| **Data & Ledger Architect** | Executor | схема PostgreSQL, миграции, целостность балансов и журналов |
| **Platform Architect** | Executor | инфраструктура, конфиги, деплой, наблюдаемость |
| **Spec Auditor** | Auditor | независимая проверка по артефактам (команда, rc, SHA), а не по отчёту |
| **Security & Payments Auditor** | Auditor | вето на merge всего, что трогает деньги, ключи и выводы |
| **Locale & UX Auditor** | Auditor | локали, тексты, доступность интерфейса |
| **Transport Maintainer** | Maintainer | ScriptCat и шлюз Drive: отдельные карточки, не «по ходу» |

Роль без строки в базе «Роли» не существует: имя, функция, зона и гейт берутся оттуда.

## 2. Один репозиторий (D-022)

Проект живёт в **`creative-textile/vault`** — это единственный репозиторий кода, документов и
транспорта. Отдельного «закрытого» репозитория нет: границы задаются зонами ролей и гейтами, а
не видимостью репозитория. Ссылка на посторонний репозиторий вместо цели — дефект карточки.

- Свой репозиторий и ветка — в техблоке задания. Ветка сессии — та, что выдана; `main` не трогать
  напрямую.
- Нужен файл, которого не видишь, — ошибка карточки: пиши в отчёт, ход не останавливай.
- Секреты (токены Notion/GitHub, ключ шлюза, ключи кошельков, пароли) не попадают в чат, логи,
  документы и Git. Боевые значения вводит только Мастер.

## 3. Инструменты уже в репозитории

- Транспорт агентов — `tools/script-cat/**`: сборка `node tools/script-cat/build.mjs`, проверка
  `node tools/script-cat/build.mjs --check`, пробы `npm test` / `npm run test:regression`.
- Узел проверки — `tools/relay-build.mjs`, сторож — `tools/relay-watchdog.mjs`.
- Продукт — `backend/`, `frontend/`, `bot/`, база — `backend/src/db/**`, схема — `init.sql`.
- Ставить с нуля не нужно ничего: сначала читай `README.md` и `docs/agents/onboarding.md`.

## 4. Зоны и гейты

| Зона | Что можно |
|---|---|
| Своя | править всё, что проходит гейт |
| Чужая | только читать; правка — карточкой владельцу |
| Оракул | только дополнять; ослаблять нельзя никому, включая Warden и Coordinator |

- `tools/script-cat/**` — защищённая зона: только отдельной карточкой Transport Maintainer.
- Деньги и выводы (`backend/src/services/ton.ts`, `services/chain/**`, админ-выводы): гейт —
  зелёный оракул **и** письменная проверка Security & Payments Auditor; без неё merge запрещён.
- Гейт любой карточки — PR в `main` после зелёного оракула. Merge делает исполнитель, а не
  приёмка; `merged: true` — только после фактического merge.

## 5. Фазы, миссии, цикл хода

Фаза — рамка, миссия — работа внутри рамки. План фаз — `docs/PHASES.md`; сейчас активна **Ф1
«Ядро продукта и 3D»**, первая миссия — **V-1-1** (`docs/missions/V-1-1.md`): пересобрать сейф,
ракету и монету под бюджет телефона. Продуктовый код открыт **только в границах scope миссии**;
всё остальное по-прежнему заморожено. Миссия начинается только после ТЗ Warden:
`docs/missions/TEMPLATE.md`, архив старых — в `docs/missions/archive/`.

Цикл хода. 1. Warden пишет ТЗ → строка в «Миссиях». 2. Coordinator: `Draft → Ready` и выдача хода.
3. Transport пишет лог в Drive, карточка идёт `Running → Submitted`. 4. Исполнитель завершает
отчёт маркером `CF_AGENT_RESULT` с реальными `dispatch_id`/`run_id`; `merged: true` — только после
фактического merge. 5. Coordinator: `Accepted` или `Rework` с причиной. 6. `next: "done"` —
передача Warden. 7. Warden: `accept` / `rework` / `master`. 8. `master` — только когда без
Мастера физически нельзя.

Зелёная карточка не заменяет финальный оракул миссии. Маркер не заменяет отчёт.
Формат финальной строки всегда стоит в самом конце задания — читай его там, а не по памяти.
Если строки формата нет — сдай отчёт и скажи об этом.

## 5a. Визуал: SVG или генерация изображения (D-111)

Инструмент выбирается по природе картинки, а не по привычке: **иконки, лого, пиктограммы UI,
рамки, болты, слоты, диаграммы — SVG** (вектор, чёткий на любом DPI, цвет из палитры, ≤20 КБ);
**фоны, ключевые кадры, атмосфера, обложки, референсы, текстуры — генерация изображения**
(свет и материал, которые вектор даст «пластиком»); **объём и силуэт — Blender** (`tools/modeling/`),
картинка 3D не заменяет. Сгенерированное изображение агент **открывает глазами** до сдачи:
силуэт читается в 128 px, палитра из `docs/art-direction.md` §4, фон пригоден для вырезания.
PNG вместо иконки или вектор вместо ключевого кадра — дефект, а не вкусовщина. Лицензии:
своё — без атрибуции, скачанное — строка в кредитах, иначе файла нет.

## 6. Доказательство вместо отчёта

`not run`, тайм-аут, зелёный CI и мок **не равны** pass. Карточка закрывается командой, кодом
возврата, артефактом и SHA. Визуальный критерий — агент сам открыл PNG и описал, что видит.

Оракул Vault: `npm run verify` (успех = код 0 и `# fail 0`) для продукта; для транспорта —
`npm run scriptcat:check`, `npm run scriptcat:guard`, `npm test`, `npm run test:regression`;
для схемы — двойной прогон `init.sql` + `schema-check` на PostgreSQL 16; для платежей —
прогон на testnet с хешем транзакции и сверкой баланса.

## 7. Деньги и режимы

Три положения проекта, переключает Мастер, не агент: **demo → testnet → mainnet**. В demo ничего
реального не двигается; в testnet платёж доказывается на тестовой сети; в mainnet деньги реальны.
Агент не «включает» боевой режим и не вводит боевые ключи — он готовит код и проверки, а переключает
Мастер. Вывод средств идемпотентен, сверяется ончейн и не может быть выполнен дважды.

## 8. Вопросы и ADR

Вопрос — только полем `question` в маркере, с вариантом по умолчанию (по нему работа идёт сразу).
Неоднозначность решай сам: минимальное изменение + строка «Допущение: …» в отчёт. Изменение
контракта, оракула или границ продукта — предложение `ADR:` с тремя вариантами и `default:
«оставить как есть»`; срок и дефолт решением не являются. Опрос «можно?» — остановка хода.

Без Мастера не решается: лицензии и ToS, деньги и комиссии, платные серверы, юридические limits
(в том числе азартные механики), целевая аудитория, доступы и аккаунты.

## 9. Запреты

Не включать боевые платежи без Мастера. Не хранить секреты в Git. Не ослаблять оракул. Не
создавать пустые сервисы «под будущие фазы». Не обещать пользователю выплат, которых нет в коде.
Не менять чужие зоны мимо карточек. Не выходить за scope миссии. Не ставить тяжёлый
инструмент «руками в /tmp»: только скриптом из репозитория с проверкой версии/хеша — песочница
откатывается.

## 10. Язык

Документы процесса и общение с Мастером — по-русски. Код, идентификаторы и коммиты — по-английски.

Продукт — **два языка: ru и en** (D-112/D-114), база — русский. Новый текст UI не хардкодь в
разметку: строки отдельно от логики, суммы и даты через форматтер с локалью, плюрализация по
числу. Язык определяется по `language_code` Telegram (`en` → en, всё остальное → ru); ручной выбор
игрока сильнее, молча язык не меняется. Названия игр **переводятся** (Сейф → Safe, Ракета → Rocket,
Дуэль → Duel), в английском UI **кириллицы нет нигде**; исключение — знак Vault. Юридически значима
русская редакция. Диагностика — код + параметры. Существующий текст переносится отдельной миссией.

## Примечание для сопровождающего (в промпт не попадает)

Сборка транспорта вшивает всё, что выше маркера `build:meta`, в бандл вместо плейсхолдера
`@@REGULATION_DIGEST@@`: агент получает эти правила вместе с заданием и не читает страницу Notion
каждый ход. Полная версия — `docs/REGULATION.md`, её номер обязан совпадать с номером в первой
строке этого файла.

Правила работы с файлом: меняете текст — пересоберите бандл (`node tools/script-cat/build.mjs`);
объём выше маркера — не больше 9000 знаков. Расхождение ловит
`tools/script-cat/regulation-oracle.mjs` в `npm run verify`, поэтому устаревшая копия в бандле
не доживёт до агента.
