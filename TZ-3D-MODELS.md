# ТЗ: 3D-модели и анимации для VAULT (полные полномочия исполнителю)

> **Кому адресовано.** Исполнителю (человеку или ИИ-агенту), который самостоятельно
> находит/создаёт 3D-ассеты, пишет код их интеграции и сдаёт результат. Все
> художественные и технические решения в рамках этого документа исполнитель
> принимает сам — согласования не требуются. Требуется только соблюдение
> «жёстких ограничений» (раздел 3) и критериев приёмки (раздел 10).
>
> **Что сдаётся.** Файлы ассетов в репозитории + код интеграции + отчёт
> (раздел 12). Работа считается принятой, когда CI зелёный, а четыре игровые
> сцены выглядят как продукт, а не как набор примитивов.

---

## 1. Контекст: что за проект и где живут сцены

**VAULT** — Telegram Mini App: игровая платформа (Ракета, Дуэль, Сейф, Vault Вклад),
валюта USDT в сети TON. Запускается внутри WebView Telegram на телефонах
(основная аудитория — Android среднего и низкого уровня), а также в обычном браузере.

Стек клиента: **React 18 + TypeScript + Vite + Three.js** (чистый Three.js,
БЕЗ react-three-fiber). Все сцены — в `frontend/src/three/`:

```
frontend/src/three/
├── lib/
│   ├── stage.ts          createStage() / createStageSafe() / startLoop() / detectQuality()
│   │                     renderer + камера + окружение + bloom + ресайз + авто-снижение качества
│   ├── environment.ts    getEnvironment(renderer, preset) — процедурная «неоновая студия»,
│   │                     запекается через PMREMGenerator. Пресеты: 'vault'|'rocket'|'duel'|'safe'
│   ├── materials.ts      gold/polishedGold/chrome/darkSteel/paintedHull/paintedRed/composite/
│   │                     glass/neon/additive/velvet + disposeObject(root)
│   ├── particles.ts      ParticleField (CPU-частицы: искры, пыль, дым, обломки)
│   ├── rng.ts            createRng(seed) — детерминированный PRNG (реплеи!)
│   └── textures.ts       процедурные canvas-текстуры (brushedMetal и т.п.)
├── main/VaultScene.tsx       сейф-витрина (онбординг/главная), prop: { size?: number }
├── rocket/RocketScene.tsx    props: { phase: 'idle'|'flying'|'crashed'|'cashed', multiplier?,
│                             cashoutAt?, crashAt?, onReady?, onGhostFinished?, seed? }
├── duel/DuelScene.tsx        props: { phase: 'idle'|'flipping'|'result', result?: 'heads'|'tails',
│                             trajectory?: { rotation_speed, height, bounces, final_angle }, onFinish? }
└── safe/SafeCrackScene.tsx   props: { phase: 'idle'|'spinning'|'result', code?: number[],
                              drumSpeeds?: number[], onDrumStop?, tapDrum?, crackable?,
                              startedAt?: number, taps?: (number|undefined)[] }
```

**Сейчас все объекты собраны кодом из примитивов** (цилиндры, боксы, торы) +
процедурные canvas-текстуры. Это работает, воспроизводимо в реплеях и ничего не
весит, но выглядит бедно: нет фасок, нет износa материалов, пропорции «коробочные»,
детализация нулевая. Заказчик оценил текущие модели как «ужасные» — это и есть
причина задачи.

**Как сцена подключается к React.** Компонент создаёт `<div ref className="three-container" />`,
в `useEffect` вызывает `createStage(...)`/`createStageSafe(...)`, строит объекты,
запускает `startLoop(stage, (dt, elapsed) => { ... })` и в cleanup уничтожает всё:
`disposeObject(scene)`, `stage.dispose()`, `particles.dispose()`. Новый код обязан
следовать тому же жизненному циклу (иначе в WebView течёт память GPU).

## 3. Жёсткие ограничения (нарушать нельзя)

1. **Никаких внешних хостов и CDN.** Все ассеты лежат в репозитории
   (`frontend/public/models/…`) и отдаются нашим nginx. Telegram Mini App может
   не иметь доступа к сторонним доменам, а внешний CDN — это ещё и зависимость
   availability. Никаких `https://...` в URL моделей/текстур.
2. **Детерминизм реплеев.** Реплей раунда (`/replay/:game/:id`) обязан показать
   ровно ту же картинку по сохранённым параметрам. Поэтому:
   - анимация модели проигрывается **от явного времени** (`mixer.setTime(t)`),
     а не накоплением `mixer.update(delta)`;
   - всё случайное — только через `createRng(seed)` из `lib/rng.ts`
     (seed приходит с сервера как `replay_seed`);
   - `Math.random()` в сценах запрещён.
3. **Игровая логика неприкосновенна.** В Сейфе три барабана с цифрами — это
   геймплей: цифры обязаны совпадать с кодом сейфа, а моменты остановки
   вычисляются из `startedAt`/`taps`/`drumSpeeds`. **Барабаны остаются
   процедурными** (их рисует текущий код), модель заменяет только корпус, дверь,
   засовы, колесо, петли и свет. То же в Дуэли: траекторию монеты считает
   серверный `trajectory`, модель не имеет права менять физику броска.
4. **Бюджет ассетов и бандла** — раздел 9. Превышение = не принято.
5. **Не ломать CI.** `cd frontend && npx tsc --noEmit && npm run build` обязаны
   проходить; `three`-чанк не должен вырасти больше чем на **120 КБ** ( gzip ) —
   то есть декодеры сжатия подключаем осознанно (см. 9.3).
6. **Стилистика едина.** Дизайн-система «Neon Vault Luxury»: тёмный фон, золото
   `#f5c542`, циан `#22d3ee`, пурпур `#a855f7`, тёплый софит сверху + цветные
   rim-панели. Модель обязана вписаться в этот свет (PBR-материалы, metalness/
   roughness), а не принести «свой» мультяшный стиль.

## 4. Спецификация ассетов

### 4.1 Общие требования ко всем моделям

| Параметр | Требование |
|---|---|
| Формат | **`.glb`** (glTF 2.0, binary, один файл). `.gltf`+bin+textures — не принимать |
| Единицы/масштаб | метры; объект реального размера (сейф ≈ 1,8 м в высоту). Лоадер всё равно нормализует, но исходник должен быть вменяемым |
| Оси | Y-up, «лицо» объекта в сторону +Z (как смотрит камера) |
| Origin (pivot) | у сейфа — **на петле двери** (ось вращения), у ракеты — в центре масс/сопла, у монеты — в геометрическом центре |
| Полигонаж | герой (сейф) ≤ **35 000** треугольников; ракета ≤ **18 000**; монета ≤ **8 000** |
| Материалы | ≤ **4** на модель; все `MeshStandardMaterial`/`MeshPhysicalMaterial` (PBR metalness-roughness). Никаких материалов, которых нет в three.js |
| Текстуры | ≤ **2048×2048** для героя, ≤1024 для остальных; **KTX2/Basis** (`.ktx2`) или, если KTX2 не вытягивает по бюджету бандла, PNG/WebP ≤ 1024. Обязательны `map`, `normalMap`, `roughnessMap`, `metalnessMap`; желательны `aoMap` и `emissiveMap` |
| UV | без перекрытий (кроме симметрии), без «растянутых» островов; texel density ровный |
| Имена | латиница, snake_case: `safe_body`, `safe_door`, `bolt_01`… Без `Cube.017` |
| Скелет | НЕ нужен: только keyframe-анимация объектов (скелетная допустима, но увеличивает вес и усложняет детерминизм) |
| Свет/камеры в файле | удалить: свет ставит наш `stage` + `environment` |
| Файл на диске | ≤ **2,5 МБ** для сейфа, ≤ 1,2 МБ для ракеты, ≤ 0,6 МБ для монеты |

### 4.2 Якорные пустые объекты (обязательно для сейфа)

Чтобы наш процедурный код «вклеился» в модель, в `.glb` должны быть пустые
узлы (Empty/locator) с точными именами:

| Имя узла | Назначение |
|---|---|
| `Anchor_Drums` | точка, куда код ставит блок из трёх барабанов (центр среднего барабана) |
| `Anchor_DrumL`, `Anchor_DrumR` | оси левого и правого барабана (не обязательно, если `Anchor_Drums` + шаг 0,80 по X) |
| `Anchor_Light` | точка внутреннего золотого света (когда дверь открыта) |
| `Anchor_Sparks` | точка эмиссии искр при остановке барабана |
| `Anchor_Floor` | уровень пола (низ модели) |

Код читает их так: `gltf.scene.getObjectByName('Anchor_Drums')?.getWorldPosition(v)`
и ставит туда свою группу. Если якорей нет — интеграция считается непройденной.

### 4.3 Геометрические рамки сейфа (взяты из текущего кода, менять нельзя)

Сцена построена под эти числа (`safe/SafeCrackScene.tsx`):

```
FLOOR_Y  = -1.78      // пол
DOOR_R   =  1.42      // радиус круглой двери
DOOR_Y   =  0.30      // центр двери по высоте
HINGE_X  = -1.55      // ось петли (дверь распахивается вокруг левого края)
DRUM_R   =  0.33      // радиус барабана
DRUM_W   =  0.46      // ширина барабана
DRUM_Y   =  0.18      // высота осей барабанов
DRUM_XS  = [-0.80, 0, 0.80]   // три барабана
Камера: fov 40, position [0.35, 0.62, 6.6], смотрит на ~(0, 0.25, 0); контейнер 4:3
```

Следовательно модель сейфа обязана:
- иметь проём/окно под барабаны, в которое вписывается блок
  `x ∈ [-1.13, +1.13]`, `y ∈ [-0.15, +0.51]`, глубиной ≥ 0,5 (барабаны стоят
  «утопленно», с рамкой-обечайкой вокруг);
- иметь дверь радиусом ≈ 1,42 с центром ≈ (0; 0,30) и петлёй на x ≈ −1,55;
- стоять на полу y = −1,78 (низ корпуса на этой высоте);
- общая высота ≈ 3,6–4,2 единицы, ширина ≈ 3,2–3,6, глубина ≈ 1,6–2,2 — так,
  чтобы при fov 40 с z = 6,6 объект занимал ~70–80% высоты кадра;
- дверь открываться **на себя-влево** (вращение вокруг Y на ≈ −1,1…−1,3 рад).

### 4.4 Анимации (клипы) — что должно быть в файле

| Клип | Длительность | Семантика |
|---|---|---|
| `idle` | 2–4 с, loop | «дыхание»: микро-поворот колеса, мерцание индикатора, лёгкий ход засовов. Амплитуда маленькая (≤ 2°) |
| `spin` | 1–2 с, loop | колесо крутится, засовы вибрируют (фаза взлома) |
| `open` | **2,4–3,0 с**, one-shot | последовательно: (0,0–0,45) засовы утапливаются → (0,35–1,25) колесо докручивается на ~3π → (1,15–2,8) дверь распахивается → (2,4–3,0) лёгкий overshoot/отскок |
| `close` (опц.) | 1,5–2 с | обратное закрытие |

Код привязывает время клипа `open` к уже существующей переменной `openSeq`
(секунды от начала открытия), то есть `mixer.setTime(clamp(openSeq, 0, duration))`.
Поэтому **тайминги внутри клипа должны совпадать с текущей процедурной
раскадровкой** (она задаёт `boltRetract`, `wheelSpin`, `doorOpen`):

```
boltRetract = clamp(openSeq / 0.45, 0, 1)
wheelSpin   = easeOutCubic(clamp((openSeq - 0.35) / 0.9, 0, 1)) * 3π
doorOpen    = easeInOut(clamp((openSeq - 1.15) / 1.6, 0, 1))   // * 1.12 рад
```

Допускается (и приветствуется) сделать клип выразительнее — но тогда исполнитель
сам правит константы в сцене, чтобы DOM-тайминги (открытие двери по времени
взлома) не разъехались с картинкой. Итог: `open` ≤ 3,0 с.

### 4.5 Что должно прилагаться к модели (пакет поставки)

Обязательно:
1. `models/<name>.glb` — финальный, сжатый, с якорями и клипами.
2. `models/<name>.license.txt` — лицензия и автор (или «CC0 / сгенерировано,
   ограничений нет»). Без этого файла ассет не принимается.
3. `models/<name>.preview.png` (или `.jpg`, ≤ 400 КБ) — 2–3 рендера: общий вид,
   крупный план материала, кадр открытой двери. Нужны для ревью без запуска WebGL.

Желательно (ускоряет ревью и правки):
4. Исходник `.blend` (или `.fbx`/`.obj` + текстуры) в `models/src/` — если
   лицензия позволяет распространение исходника.
5. Отдельные карты в `models/src/textures/` (albedo/normal/roughness/metalness/AO/emissive).
6. LOD1 (уполовиненный полигонаж) — для `quality === 'low'`.
7. README ассета: сколько треугольников, сколько draw call, чем сжимали.

## 5. Где брать модели (исполнитель выбирает сам)

**Вариант A — готовые библиотеки.** Poly Haven (CC0), Quaternius (CC0), Kenney
(CC0), Sketchfab (CC0/CC-BY/платные), CGTrader, TurboSquid, Free3D, Sketchfab
Store. Искать по запросам: `bank vault door`, `safe door animated`, `metal safe
box`, `vault door mechanism`, `gold coin pbr`, `stylized rocket ship`.
Обязательная проверка: есть ли анимация открытия (или можно ли её сделать самому
в Blender — обычно да, это 1–2 часа работы).

**Вариант B — генерация.** Meshy AI, Tripo3D, Luma Genie, Hunyuan3D, Rodin.
Плюс: быстро и уникально. Минус: «мыльная» топология и почти никогда нет
анимации. Поэтому после генерации обязателен проход в Blender: decimate/retopo,
чистка UV, запекание normal + roughness, разделение на объекты
(`safe_body` / `safe_door` / `bolts` / `wheel`) и ключевая анимация.

**Вариант C — доработка текущей процедурной геометрии** (Plan B, см. раздел 11).
Если за разумное время не нашлось/не собралось модели, удовлетворяющей разделу 4,
исполнитель улучшает код: фаски (`LatheGeometry`/`ExtrudeGeometry` с bevel),
панельные швы, заклёпки, карты износа по кромкам, правильное членение
пропорций, стекло с `transmission`, более богатый свет. Это приемлемый результат,
но только если A и B объективно не вышли — факт нужно обосновать в отчёте.

**Пайплайн обработки (единый для всех вариантов):**
```
Blender:  импорт → чистка (удалить свет/камеры/пустые меши) → Apply All Transforms
          → Decimate до бюджета → UV → запекание карт → проверка pivot и осей
          → добавить Empty-якоря (4.2) → keyframe-анимация (4.4)
          → Export glTF 2.0 (.glb): +Y up, Apply Modifiers, без Cameras/Lights,
             Animation: включено, Shape Keys: только если нужны
CLI:      npx gltf-transform inspect  model.glb     # треугольники/материалы/текстуры
          npx gltf-transform prune    model.glb out.glb
          npx gltf-transform dedup    out.glb out.glb
          npx gltf-transform resize   out.glb --width 1024      # (или 2048 для героя)
          npx gltf-transform etc1s    out.glb out.glb           # KTX2-сжатие текстур
          npx gltf-transform meshopt  out.glb out.glb           # сжатие геометрии
          npx gltf-transform inspect  out.glb     # финальный отчёт → в отчёт о работе
```

## 6. Код, который нужно написать

### 6.1 Новый модуль `frontend/src/three/lib/models.ts`

Точный контракт (имена обязательны — на них завяжутся сцены):

```ts
export interface LoadedModel {
  /** Корень для добавления в сцену (уже нормализован и поставлен на пол). */
  root: THREE.Group;
  /** Клипы по имени: 'idle' | 'spin' | 'open' | 'close'. */
  clips: Record<string, THREE.AnimationClip>;
  /** Микшер: время задаём явно — mixer.setTime(t). */
  mixer: THREE.AnimationMixer;
  /** Якоря из 4.2 (пустые объекты, которых может не быть). */
  anchors: Record<string, THREE.Object3D | undefined>;
  /** Сколько треугольников реально отрисовывается (для отчёта/деградации). */
  triangles: number;
}

export interface ModelOptions {
  /** Целевая высота объекта в единицах сцены (Bounding Box → scale). */
  targetHeight?: number;
  /** Поставить низ модели на этот Y (по умолчанию — 0). */
  floorY?: number;
  /** Качество: влияет на выбор LOD, карты, transmission. */
  quality?: 'high' | 'medium' | 'low';
  /** Замена/дополнение материалов (например, включить emissive у индикатора). */
  onMaterial?: (m: THREE.Material, name: string) => void;
}

/** Загрузить .glb из /models/<file>. Кэш по URL: вторая сцена не грузит повторно. */
export function loadModel(file: string, opts?: ModelOptions): Promise<LoadedModel | null>;

/** Синхронно взять уже загруженную модель из кэша (null, если ещё не готова). */
export function peekModel(file: string): LoadedModel | null;

/** Освободить одну модель / все (вызывается в cleanup сцены). */
export function disposeModel(file: string): void;
export function disposeModels(): void;
```

Требования к реализации:
- `GLTFLoader` из `three/addons/loaders/GLTFLoader.js`; при использовании
  meshopt/KTX2 — подключить соответствующие декодеры (`MeshoptDecoder`,
  `KTX2Loader` + `basis`-транскодер). **Если декодер тянет > 120 КБ gzip в бандл —
  не использовать его, отдать модель без сжатия геометрии** (см. 9.3).
- Ошибку загрузки **глотать** и возвращать `null`: сцена обязана отрисовать
  процедурный fallback (раздел 6.3), а не показать чёрный экран.
- Нормализация: посчитать `Box3`, привести высоту к `targetHeight`, сдвинуть так,
  чтобы низ встал на `floorY`, а центр по X/Z — в 0.
- `triangles` — сумма `geometry.index.count/3 || position.count/3` по мешам.
- Кэш — `Map<string, Promise<LoadedModel|null>>`, чтобы две сцены
  (`SafeCrackScene` и `VaultScene`) не грузили файл дважды.

### 6.2 Интеграция в сцены

**Сейф (`safe/SafeCrackScene.tsx`, критично).**
1. В начале `useEffect` вызвать `loadModel('safe.glb', { targetHeight: 4.0, floorY: FLOOR_Y, quality })`.
   Загрузка асинхронна → до её завершения сцена показывает **текущий процедурный
   сейф** (он уже есть); после загрузки модель подменяет корпус.
2. Из модели взять `anchors.Anchor_Drums` и перенести туда существующую группу
   барабанов (`drums`), сохранив их процедурную логику (цифры, `onDrumStop`,
   `taps`, `drumSpeeds` — не трогать!).
3. Анимация: `openSeq` → `mixer.setTime(...)` для клипа `open`; в фазе `spinning`
   — клип `spin` (зациклить через `mixer.setTime((elapsed % dur))`); в `idle` —
   клип `idle` тем же способом. **Никаких `mixer.update(dt)`** — только явное время.
4. Процедурные `boltRetract`/`wheelSpin`/`doorOpen` оставить как fallback и как
   источник для света/частиц (золотое свечение изнутри, искры, пыль) — их
   интенсивность уже привязана к `doorOpen`.
5. Свет изнутри и `Anchor_Light`: поставить `PointLight` (или перенести
   существующий `goldLight`) в точку якоря.
6. Cleanup: `disposeModel('safe.glb')` — только если сцена была последним
   потребителем (или просто не освобождать кэш между сценами, освободить при
   размонтировании App; решение за исполнителем, но утечки быть не должно).

**Витрина (`main/VaultScene.tsx`).** Та же модель `safe.glb`, фаза `idle`,
другой ракурс. Дублировать геометрию кодом больше не нужно.

**Ракета (`rocket/RocketScene.tsx`).** Модель `rocket.glb` вместо процедурной
`buildRocket()`; сохранить существующие точки привязки: пламя двигателя
(`flameCore`/`flameMid`/`flameOuter`), дым, обломки, камера следует за объектом.
Требуется найти/создать в модели узлы `Anchor_Flame` (сопло) и `Anchor_Nose`.
Детерминизм: `seed` (`replay_seed`) по-прежнему задаёт звёзды/обломки через `createRng`.

**Монета (`duel/DuelScene.tsx`).** Модель `coin.glb` с нормализацией под
`COIN_R = 1.18`, `COIN_T = 0.16` (то есть `targetHeight = 2*COIN_T` при стоянии
на ребре — или нормировать по диаметру: `targetHeight = 2*COIN_R`, тогда толщина
проверяется отдельно). Траектория (`rotation_speed`, `height`, `bounces`,
`final_angle`) и `REST_Y`/`SHOWCASE_Y` не меняются.

### 6.3 Fallback и деградация качества (обязательно)

- `quality === 'low'` → модель НЕ грузим вообще (или грузим LOD1, если он есть),
  остаётся процедурная геометрия. Порог уже считает `detectQuality()`.
- Ошибка сети/парсинга → `null` → процедурная геометрия. Пользователь не должен
  видеть пустую сцену.
- Пока модель грузится, показываем процедурную (никаких «скелетонов» и спиннеров
  поверх canvas).
- Если `stage.tickPerf()` деградировал качество на лету (слабый FPS) — модель
  остаётся, но отключаются дорогие материалы (`transmission`, `clearcoat`) и тени.

## 7. Художественные требования (что значит «не ужасно»)

1. **Фаски везде.** Ни одной острой кромки под 90°: chamfer/bevel 1–3 см на
   реальных объектах. Именно фаски дают блик, по которому глаз считывает «дорого».
2. **Износ материала.** Roughness-карта с потёртостями на кромках, углах и там,
   за что берутся руками; micro-scratch normal map (не «пластиковый» глядец).
3. **Членение пропорций.** Сейф: массивный корпус + заметно более тонкая
   декоративная рама двери + крупное колесо + 6–8 засовов по периметру +
   видимые петли. Монотонный куб с кружком читается как «коробка».
4. **Материалы по PBR.** Тёмная сталь (metalness ~0,9 / roughness 0,35–0,5),
   полированное золото (metalness 1 / roughness 0,12–0,25), матовая краска
   корпуса, стекло/индикатор с emissive. Все значения — из `lib/materials.ts`,
   чтобы модель и процедурные части сцены не спорили.
5. **Свет не «вшивать».** Никаких запечённых светлых/тёмных пятен в albedo:
   свет ставит сцена (`environment.ts` + bloom). Запекать можно только AO.
6. **Читаемость в кадре.** Объект рассматривают на телефоне, в кадре ~70% высоты,
   в движении и с bloom. Мелкая детализация (< 2 см) бессмысленна — она исчезнет.
7. **Единая палитра.** Золото `#f5c542`, циан `#22d3ee`, пурпур `#a855f7`,
   красный сигнал `#ff3b5c`, тёплый софит. Индикаторы сейфа — циан (ожидание) /
   красный (взлом) / золото (открыт).

## 8. Производительность

- Цель: **60 FPS** на устройстве уровня Snapdragon 7xx / 4 ГБ RAM и **≥ 30 FPS**
  на слабом Android (там `quality === 'low'`, модель не грузится).
- Draw calls на сцену: ≤ **25**. Материалов ≤ 4 → это достижимо; больше — объединять.
- Тени: только `quality === 'high'`, один источник, карта ≤ 1024.
- `transmission` (стекло) — только `high` (на слабых устройствах это 12–18 FPS).
- Проверка в `dev/scenes.tsx` (6.4) — обязательный скриншот показателей в отчёте.

## 9. Бюджет

### 9.1 Ассеты
Суммарно все модели ≤ **4,5 МБ** в `frontend/public/models/` (сейф ≤ 2,5,
ракета ≤ 1,2, монета ≤ 0,6, HDRI ≤ 0,4 если делаем).

### 9.2 Первая загрузка
Модель грузится **лениво** — только когда пользователь открыл соответствующий
зал, и не блокирует первый кадр. `preload` на главной (сейф-витрина) допустим
через `requestIdleCallback` после первого рендера.

### 9.3 Код и бандл
- `GLTFLoader` (~40–60 КБ gzip) — обязательный расход, попадает в чанк `three`.
- `MeshoptDecoder` ~30 КБ — допустимо.
- `DracoDecoder` (wasm ~300 КБ) — **запрещён**, если только это не единственная
  возможность вписаться в 2,5 МБ для сейфа. Обоснование — в отчёте.
- `KTX2Loader` + basis-транскодер (~150 КБ wasm) — применять, только если
  выигрыш по текстурной памяти ≥ 3× (проверить `gltf-transform inspect` до/после).
- Итог: рост чанка `three` ≤ **120 КБ gzip** (сейчас `three-*.js` ≈ 500 КБ raw /
  ≈ 128 КБ gzip).
